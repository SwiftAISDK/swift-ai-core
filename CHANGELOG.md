# Changelog

## 1.6.0

- Upstream parity audit of `ai` and `@ai-sdk/provider-utils`. `AI.generateImage` now splits `count` above the model's `maxImagesPerCall` (new `ImageModel` requirement, default 1, plus a call-level `maxImagesPerCall:` and `AIImageModelMiddleware.overrideMaxImagesPerCall`) into concurrent calls with per-call retries. Retries report `maxRetriesExceeded` after the budget and parse `retry-after(-ms)` like upstream; embedMany merges provider metadata across chunks and reports `ai.embedMany`; rerank skips empty documents and fills response metadata; empty-text reasoning with provider metadata is replayed between steps and kept by UI conversion. `isURLSupported` matches media types exactly, JSON parsing follows `JSON.parse`, `withoutTrailingSlash` removes one slash, caller `Content-Type`/`User-Agent` override defaults case-insensitively and streamed tool-call IDs use upstream's 16-character form. New helpers `aiFunctionToolInputSchema` (and related accessors) and `validateBaseURL`.
  Compatibility: Additive public API (protocol requirement with a default, new parameters with defaults, new helpers). Custom `ImageModel` conformers without a limit now receive one image per call, as upstream; declare `maxImagesPerCall` to keep larger calls.
